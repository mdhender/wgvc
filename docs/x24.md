# Desirability-field growth

Issue #24 replaces inter-island distance rules with a static desirability field.
Issue #25 adds a permanent ocean barrier and a configurable edge ramp. Issue #26
guarantees regional attractant coverage when the configured ramps leave enough
room. Issue #42 replaces one-hop control with a rival ramp by hop distance to
other islands' land. This algorithm now drives the public generator.
`generate` exposes its controls without expanding the public API.

The algorithm builds the same relaxed, world-level Voronoi mesh as the current
generator. Any cell whose polygon enters the outer 0.02 map-unit strip is
permanently ineligible for land. Starting with the first eligible hop past that
barrier, the edge field defaults to `-1,-0.65,-0.40,-0.22,-0.10,-0.04,0` and
stays neutral beyond the end of the sequence. Multi-source propagation keeps
the harsher value where paths from different edges meet.

The map is divided into 3×3 regions. The `-attractors` flag accepts 0, 1, 2, 3,
4, 5, 6, or 9 and defaults to 0. Counts 1 through 6 select regions in the same
pattern as pips on a six-sided die; 9 selects every region. Each selected region
gets a target near its center, jittered by the round RNG, and selects the nearest
cell that satisfies edge clearance. The default jitter is 0.65 of the distance
from a region center to its edge. If no cell in a selected region is far enough
from the map edge, that region is skipped and `generate` logs the reason without
restarting the round. `-attractors` also accepts a constellation name
(`ursa-minor`, the seven stars of the Little Dipper; `cygnus`, eight stars of
the Northern Cross with the body north to south; `virgo`, eleven stars spread
west to east along the ecliptic; or `subaru`, twenty-one sites shaped like the
Japanese archipelago rather than a real constellation): each star becomes an
attractant at its projected position, scaled uniformly so the figure fills 76%
of the map's width or 70% of its height, and placed on the nearest cell with
edge clearance. Constellations use no jitter and consume no randomness, so the
sites are the same for every seed. The first islands, up to the number of
stars, are seeded on the star cells so that each star grows its own island;
any further islands draw uniform seeds as usual. Each constellation names the
aspect ratio it was drawn for (`2:1` for `ursa-minor` and `virgo`, `3:2` for
`cygnus`, `5:2` for `subaru`, `16:9` for `draco`), which `generate` uses when
`-aspect` is not given, and may name an ocean fraction (`draco` uses 0.86)
used the same way when `-ocean` is not given. `draco` is one kin group of
thirty-seven sites, a dragon whose twelve-site head rings a full-strength
repulsor to hold an inland sea; sites are spaced every 0.16 of the frame so
the chain stays joined at its thin 86% ocean.

A constellation may list kin groups of sites. Islands seeded on kin sites
share one group: the rival ramp is computed by group rather than island, so
kin islands see each other's land at the static value and merge when they
touch, while the deck keeps one entry per absorbed kin island so the merged
landmass draws as often as its stars did. Islands outside any group, and every
island without a constellation, behave exactly as before. `subaru` uses a
twelve-site mainland, a four-site northern island, and a two-site southwestern
island.

Sites may carry weights. A positive weight is the island's share of growth
draws: the deck then draws islands in proportion to their weights (only when a
constellation supplies weights, so unweighted worlds keep the same draws), and
kin merges keep each absorbed member's weighted entry. A negative weight makes
the site a repulsor: it seeds no island and no attractant, and the repulsor
ramp, scaled by the weight's magnitude, is subtracted from the static field
around its cell before growth begins, then clipped to `[-1, 1]`. The default
repulsor ramp reaches nineteen hops, so one repulsor can hold open an inland
sea or a bay; `subaru` weighs its two western islands 0.5 and places three
repulsors. `-repulsor-ramp` accepts the same form as the edge ramp.

Attractants use a graph-hop ramp, defaulting to
`1,0.78,0.58,0.42,0.29,0.18,0.10,0.04,0.01,0`. A source must be more than the
sum of the edge and attractant ramp reaches from the barrier, proving that
positive attractant influence and negative edge influence cannot touch the same
cell. Overlapping attractants add together, with the completed field still
clipped to `[-1, 1]`.

Seeds are uniformly selected from unclaimed cells and use the same claim logic
as later growth. Each island sees a rival ramp on cells near land it does not
own: a cell one hop from rival land takes the first ramp value, two hops the
second, and so on, and keeps the harsher of that value and the static field.
The ramp defaults to `-1,-1,-0.5,0`, so the cell whose claim would merge two
islands, and the cell beyond it, are worth -1 against about 0 for open interior
water. Frontier selection uses a softmax with temperature 0.20, where -1 weighs
about e^-5 against a neutral cell; lowering the temperature makes the ramp
decisive, and `-rival-ramp 0` disables it.

The earlier one-hop control rule penalized only cells a rival had reached
first, but a merge is caused by the island that reaches the gap cell first,
which saw no penalty. Measured over five seeds, every merge happened on a cell
the claimer itself controlled, so `-control-penalty` never changed the merge
count. The rival ramp penalizes the claim that actually merges.

Apart from the permanent edge barrier, there is no hard spacing or
water-connectivity filter. Every eligible, unclaimed frontier cell has nonzero
probability, so interior lakes remain valid outcomes.

A claim merges every rival island whose claimed land is directly adjacent to
the newly claimed cell. The rival ramp affects desirability but is not used as
a proxy for connectivity. The winner receives all claimed cells, and each loser
leaves the deck. Final island IDs are compacted after growth, so the
rendered island count can be lower than the initial count.

Render the default configuration with:

```sh
go run ./cmd/generate
```

This writes `world.svg`; use `-format png`, `-format json`, or `-format all` for
PNG and canonical world-data output. Comma-separated combinations such as
`-format svg,json` are also accepted; `-format both` remains the SVG-and-PNG
alias.
Pass `-aspect landscape`, `portrait`, `widescreen`, or `cinematic`, or use a
numeric width:height ratio. Output dimensions are derived from the land-province
count, effective ocean percentage, and aspect ratio. Maps retain the production
terrain fills, cell borders, and coastline. Use `-edge-barrier` to tune the
permanent ocean strip, `-attractors` to select the number of attractors,
`-edge-ramp`, `-attractant-ramp`, and `-rival-ramp` to supply comma-separated
ramps, and `-attractant-jitter` to tune regional placement. Run
`go run ./cmd/generate -h` for all generation flags.
